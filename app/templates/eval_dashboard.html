Three Decisions That Mattered Most
  1. JWT over OTP-in-MCP: The original prototype asked citizens for their OTP inside the chat. We replaced this with the portal's full OAuth 2.1 flow so that (a) the AI model never sees an OTP or password, (b) the same JWT works on both citizen and officer MCPs with correct audience separation, and (c) session expiry is enforced server-side.
  2. Pilot block scope (AGENT_BLOCKS): The Director explicitly asked us to run the agent only for a subset of blocks. We enforce this in both check_eligibility and submit_application so citizens from non-pilot blocks are redirected to the counter at eligibility check time — not after they have given all their details.
  3. Declared-only age proof with officer confirmation: The agent channel cannot upload files. We store a declared://<type> marker in doc_path and surface a warning in the officer dossier. The officer must set confirmed_original_seen=True before approving a declared-only application — making it impossible for the AI to silently approve an unverified document.
One Decision We Would Make Differently

We would replace the in-process _VERIFIED dict (used as a dev fallback for OTP verification state) with a Redis-backed session store shared across multiple MCP server replicas. The current design works for a single container but breaks under horizontal scaling — which matters once the pilot expands beyond three blocks.
